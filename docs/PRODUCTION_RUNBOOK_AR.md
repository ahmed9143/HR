# Runbook الإنتاج — HR Enterprise + ZKTeco

## قبل التشغيل
1. شغّل `python PRODUCTION_PREFLIGHT.py`.
2. تأكد من وجود نسخة احتياطية سليمة.
3. غيّر كلمة مرور `admin` الافتراضية في أول دخول.
4. في بيئة الشبكة، ثبّت `HR_DB_URL` واستخدم PostgreSQL عند الحاجة لعدة مستخدمين كثيفة.

## النسخ الاحتياطي
- النسخ اليومية مفعلة افتراضيًا الساعة 23:00.
- النسخ تشمل قاعدة البيانات وملفات الموظفين.
- كل نسخة يتم التحقق منها قبل اعتمادها.
- يمكن وضع `backup_network_path` في Settings لعمل نسخة ثانية على مجلد شبكة/قرص احتياطي.
- قبل Restore يتم إنشاء نسخة أمان تلقائية.

## ZKTeco
نفّذ الاختبار على الجهاز الحقيقي:
`python ZK_HARDWARE_CHECK.py 192.168.x.x 4370 0`

الاختبار لا يغيّر بيانات الجهاز؛ يختبر الاتصال ثم قراءة سجل الحضور.

## الأعطال
- افتح System Health.
- افتح Diagnostics / Error Center.
- استخدم Request ID لتحديد الطلب الفاشل.
- لا تحذف قاعدة البيانات أو ملفات الموظفين يدويًا.

## ملاحظة مهمة
إلغاء الوظائف الخلفية في Python تعاوني؛ لا يمكن قتل Thread بالقوة بأمان. لذلك تم تقليل المخاطر عبر timeouts، retries، cancellation، وحدود الوظائف. إذا احتجت عزلًا صارمًا لعملية ZKTeco، استخدم worker process مستقل في مرحلة لاحقة.
